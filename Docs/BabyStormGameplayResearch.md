# Baby Storm 玩法调研与复刻拆解

> 公开搜索没有定位到可靠的官方 Baby Storm 商店页或说明页。本文以本仓库 `goal.md`、当前 `BabyMvp.lua` 已验证闭环，以及 Overcooked / Moving Out / Tools Up 这类混乱协作游戏的结构规律为依据。

## 一句话定位

Baby Storm 是“育儿主题的混乱协作任务游戏”：玩家在有限时间和混乱场景中识别宝宝需求，把宝宝、道具、设施正确匹配，连续完成安抚任务获取分数。

## 核心循环

1. 宝宝生成需求。
2. 玩家观察头顶气泡或状态反馈。
3. 玩家寻找匹配道具或设施。
4. 玩家搬运宝宝/道具到交互范围。
5. 系统检查匹配结果。
6. 正确则满足、加分、刷新下一需求；错误则提示、增加压力。
7. 随时间提高同时需求量、错误成本和场地干扰。

## 玩家动词

- 观察：读宝宝状态。
- 抱起/放下：移动宝宝。
- 寻找/搬运：把目标道具送到正确位置。
- 匹配：用需求规则判断正确道具。
- 协作：多人分工处理多个宝宝。

## 宝宝状态建议

- `Idle`：有需求，巡逻/等待，可被抱起。
- `Carried`：被玩家抱起，AI 暂停，记录携带者。
- `SeekingItem`：放下后发现正确道具，移动并拾取。
- `Satisfied`：完成需求，播放反馈并结算。
- `Upset`：错误道具或失败交互，短暂反馈后回到需求态。

## 需求扩展

| 类型 | 表现 | 解法 |
| --- | --- | --- |
| 饥饿 | 想吃蛋糕/冰淇淋 | 食物道具 |
| 口渴 | 想喝奶昔 | 饮品道具 |
| 困倦 | 打哈欠 | 床/摇篮 |
| 脏乱 | 哭闹/污渍 | 浴盆/清洁道具 |
| 玩耍 | 想玩具 | 玩具道具 |

## 复刻优先级

- P0：配置化需求、宝宝状态机、抱起/放下、正确/错误匹配、得分、头顶 UI。
- P1：需求倒计时、哭闹值、连击、设施型需求、波次节奏。
- P2：错误干扰道具、随机事件、宝宝互相影响、场景障碍。
- P3：关卡配置、成就任务、局内技能、星级评价、教程引导。

## 架构结论

宝宝应该是“活的订单”：它会移动、会被抱起、会表达情绪，也会成为场地压力源。复刻版应先把“宝宝是状态实体、需求是配置、道具是服务、表现是绑定”的骨架搭稳，再扩内容。
